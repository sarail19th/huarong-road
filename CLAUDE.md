# Huarong Road

Klotski-style sliding-block puzzle (4x5 board, slide the big red 2x2 to the bottom-centre exit). Plain HTML/CSS/JS, no framework, no runtime dependencies. Ships as one self-contained `dist/index.html` that works as an installable Android PWA (Chrome -> Add to Home screen).

## Layout
- `src/solver.js` - board model + BFS solver. Grid is 20 cells, row-major. Codes: 0 empty, 1-4 red 2x2 (TL,TR,BL,BR), 5-6 vertical 1x2, 7-8 horizontal 2x1, 9 single. One "move" = one block slid any distance in a straight line. Goal: red top-left at row 3, col 1.
- `src/daily.js` - daily puzzle, generated on the device from the local date (offline; same puzzle for everyone that day): seeded random tiling + full state-space BFS like `gen/gen.js`, par = true optimum, weekday difficulty targets (`TARGET`, Mon 14 ... Sun 62). Daily #1 = 1 Nov 2026. UMD, also used by `test/test.js`.
- `src/levels.js` - GENERATED (100 levels, `{id, par, g}`). Do not hand-edit; run the generator.
- `src/game.js` - all UI logic. Main pieces:
  - **Setup phase:** copy the LED layout; chip check = piece type at the right cell. The Auto-place toggle (default ON, `hr_auto`) pre-fills every level.
  - **Play phase:** pointer-drag sliding. Undo + Redo are grouped in one pill beside the LED; Hint + Show solution are grouped under the board; Restart sits right next to the LED (`.ledside`), at least a thumb-width (48px) from Undo, and asks first when moves would be lost. Buttons use a flat inline-SVG icon set (a `<symbol>` sprite at the top of `index.html`, drawn with `currentColor`; most shapes are adapted from Google's Material Design icons, Apache-2.0, see `NOTICE.md`; no Flaticon files).
  - **Hints:** two explained taps built from the optimal line. Tap 1 names the next goal (the blocker the line frees first, how many of the cells it needs are empty, how many moves to make room) and outlines it. Tap 2 shows the exact move plus why it helps (it is the blocker / sits on a needed cell / brings the gap next to it / empties the space the next move needs). Once a hint was used, each move shows ✓ closer / ↔ no progress / ✗ further via a lazily cached distance-to-goal, `distOf`.
  - **Solution viewer:** "Show solution" -> confirm -> step/play through the BFS-optimal line from the start position. Viewing it records the level in `hr_seen`; wins on that level earn 0 stars, forever.
  - **Settings panel** (gear, top-right on the menu and in the game). Four groups, each a rounded list with a small heading: Look & language (language, skins) · Sound & feel (sound, vibration, reduce motion) · Gameplay (auto-place, auto-start, timer) · Your data (back up, reset all). The items: language switch (`EN | TH`, active side highlighted, `hr_lang`); skin picker (8 skins: classic, blossom, neon, ocean, sunset, forest, mono, gold, all shown at once as live preview tiles; each skin is a `[data-skin=...]` block of CSS variables in `style.css` that sets every variable it uses, and a tile carries its own `data-skin` to paint itself; `hr_skin`); sound (`hr_muted`); vibration (`hr_haptics`, hidden where unsupported); Auto-place switch (`hr_auto`, same setting as the key on the setup screen, kept in sync); Auto-start switch (`hr_autostart`, default off: opening a level places the blocks and starts playing at once, skipping the chips and the Start button; it overrides Auto-place); Timer switch (`hr_timer`; off = no-stress mode: the clock and the win-card time are hidden, time is still tracked); Reduce motion switch (`hr_motion`; unset = follow the phone's `prefers-reduced-motion`; on = `<html data-motion=reduce>`, which stops every CSS animation/transition and smooth scrolling); Back up progress (opens a dialog: share the backup file through the phone's share sheet (`navigator.share`, button hidden where unsupported; Drive, Gmail, LINE...), copy a `HR1.<base64 JSON>` code or save it as a .txt file, restore from a pasted code or a file; restoring merges, keeping the best of both, and never loses progress; the dialog shows "Last backed up: ..."). Backup reminder row (`hr_bkfreq` = weekly (default) | monthly | off; tap cycles; value + last backup shown on the row; see Backup safety net below). Every switch shows On/Off (เปิด/ปิด) beside the pill. Last row: Reset all progress (red; dialog whose Reset button stays disabled until "I understand this can't be undone" is ticked, with a Back up first shortcut; clears `hr_progress` + `hr_seen`, i.e. stars, bests, solution marks and daily streaks; keeps designs and settings).
  - **Backup safety net** (there is no server, so nothing can be saved automatically): (1) `keepStorage()` calls `navigator.storage.persist()` at start and after each saved record, so the browser does not evict `localStorage` when space is low (installed apps are usually granted it silently). (2) Share / Copy / Save each call `markBacked()`, which stores `hr_bk` = `{at, stars, ds, streak, snooze, since}` (a snapshot of what the backup held; NOT part of backups, untouched by Restore/Reset). (3) A reminder banner (`#bkNudge`, top of the menu, re-checked on `showMenu`) appears only when `max(last backup, last "Later", first run)` is older than the period (7 / 30 days) AND something new is worth saving: >= 5 new stars (all keys, incl. dailies and stages), >= 1 stage not in the last backup, or a streak of 7+ that is longer than at the last backup. "Back up" opens the dialog; "Later" waits a full period; a closed share sheet does not count as a backup. If stars drop (reset), the snapshot follows them down.
  - **Language:** `EN | TH` switches every action, message, hint, grade name and the solution viewer to Thai; brand name and the game terms Moves, Par, Time, Best, Undo, Redo and EXIT stay English on purpose (`L(en, th)` in code, `data-th` attributes in the HTML for static text). The switch also lives in the About panel.
  - **Dialogs:** `openDlg`/`closeDlg` move keyboard focus into a dialog and back to the opener; Esc closes the top dialog (except the win card); Tab stays inside.
  - **Daily puzzle:** card at the top of the menu (date, streak, LED preview, grade + par, this week's row, Play). Generated once per day in a Web Worker built from the inlined `srcSolver` + `srcDaily` scripts (falls back to the main thread), cached in `hr_daily_lv`. Results live in `hr_progress` under `d<YYYY-MM-DD>` (so backups include them; they do not count toward the 300 level stars). Streak = consecutive solved days back from today (or yesterday while today is open). The win card shows streak, week row and a countdown to midnight.
  - **My stages page** (`#stages` screen, menu card -> `showStages`): summary (stages n/50, stars earned, hardest par), New stage button (disabled at 50), empty-state explanation, list of saved stages with Play / Edit / two-tap Delete. A stage played from the list returns to the list (`lv.fromList`; the win card's left button reads "My stages"); the editor's Back returns to the list; a draft test play returns to the editor. `showScreen(id)` switches menu / stages / game.
  - **Design stage** (New stage or Edit -> `openDesign`, game screen in phase `design`): tap a block type in the tray, tap the board to place it, tap a block to remove it. Rules: exactly one red 2x2, exactly 2 empty cells, any mix of tall/wide/small. Live check: rules -> equal to one of the 100 levels or its mirror image (`levelKeys`, `mirrorKey`; can be tested, not saved) -> already saved -> solver in the worker (`job({type:'solve'})`): "No solution" (plus a tip when there are fewer than 4 small blocks: measured, random legal layouts are solvable ~4% of the time with 0 small blocks, ~16% with 2, ~71% with 4, 86%+ with 6+; small blocks always come in even numbers because 14 cells remain after red + 2 gaps) or "Solvable · minimum N moves", graded with `gradeOf(par)`. Save keeps up to 50 stages (`MAX_STAGES`) in `hr_designs` = `[{n, g, par, at}]`; stars per stage in `hr_progress['s<n>']` (not counted in the 300). Saved stages play straight away (no setup); Edit reopens one (saving changes resets its record); delete is two taps. An unsaved draft's test play records nothing (id `draft`). Designs are included in backups (restore merges by layout, renumbering clashes).
  - **Per-level reset:** under the stats, "Your record: ★★☆ · Best 14 · solution viewed" + a Reset record link, shown only when the level (or own stage) has a record; never for dailies or drafts. Confirm dialog shows the record; resetting clears that level's stars, best and solution lock.
  - **Best score:** fewest moves per level, shown as a 4th stat (`Best`) once a level is cleared and on the win card ("New best!" when beaten).
  - **About panel** (`?`): 4 pages with Back/Next and dots; story behind the name, Thai-aware; numbers quoted there were checked against the solver.
  - **Menu:** collapsible "How to play" panel (open on first launch, `hr_howto`); paged level list (20 per page via chips + prev/next, `hr_page` remembers the page, opening a level moves the menu to its page); win + stars + progress in localStorage (`hr_progress`; daily cache `hr_daily_lv`).
  - **In-app updater:** the `Update` pill next to the `Version <hash>` label at the bottom of the menu probes the server, clears caches + the old service worker and reloads; a "new version ready · Update" banner shows when a new worker takes over. Progress/localStorage is never touched.
- `src/style.css`, `src/index.html` - templates with `/*INLINE_...*/` placeholders. `src/fonts/Anuphan-thai.woff2` is the Thai UI font (loopless; Thai glyphs only, weights 400-700): `build.js` base64-inlines it at `/*FONT_ANUPHAN*/` in `style.css`, and `html[lang=th]` switches to it (English keeps the system font, Latin/digits fall through the font stack).
- `gen/gen.js` - level generator (seeded, deterministic). `gen/icons.py` - PWA icons: any 192/512, maskable, monochrome (themed Android icon), apple-touch-icon 180 (needs Pillow). Design: 4x4 board, red 2x2 in the middle ringed by small corners, wide top/bottom and tall sides, green exit under the bottom wide block; blocks on whole cells with one gap size (true 1x1/2x1/1x2/2x2 proportions); no emblem on the red block (the in-game piece keeps its triangle). `gen/shots.py` - store screenshots for the manifest (wide 1280x720 + two narrow 780x1688; needs Playwright, fixed date so they are reproducible; re-run when the menu or board look changes).
- `build.js` - inlines everything into `dist/index.html`, writes the manifest (id, description, lang, categories, icons incl. maskable + monochrome, screenshots; the service worker caches every icon) (stamping `__BUILD__` with a content hash of the page + `gen/icons.py` + `build.js` that also names the service worker cache, so icon-only changes still ship; the worker fetches its files with `cache:'reload'`), writes manifest + service worker, and `dist/artifact.html` (title + style + body only, for the claude.ai Artifact tool).
- `test/pwa_test.js` - checks the manifest, icon/screenshot files and sizes, the service-worker cache list and the head tags (description, apple-touch-icon, zoom allowed). `test/test.js` - verifies every level (solvable, par == true optimum, replay is legal). `test/ui_test.py` - Playwright mobile-viewport end-to-end test (needs `pip install playwright` + Chromium).

## Commands
```
node gen/gen.js        # regenerate src/levels.js (~25 s)
node test/test.js      # must print "OK: 100 levels verified"
node build.js          # produce dist/
python3 gen/icons.py   # icons into dist/ (run after build)
python3 gen/shots.py   # manifest screenshots into dist/ (run after build; PW_CHROMIUM=<chromium path> if needed)
node test/pwa_test.js  # manifest / icons / screenshots / service-worker list
python3 test/ui_test.py
```
Serve `dist/` over https (or localhost) for the service worker to register; opening the file directly also works but skips the PWA parts.

## Rules when changing things
- Changing the solver, grid codes, or generator: re-run `node gen/gen.js` and `node test/test.js`.
- Keep `par` equal to the true BFS optimum; star rating depends on it (<= par = 3 stars, <= 1.4x par = 2).
- UI changes: rebuild and run `python3 test/ui_test.py`.
- New guidance text (hints, status, solution, about) needs a Thai version too: use `L(en, th)` in JS or `data-th` in HTML.
- Never block pinch zoom in the viewport meta (`user-scalable=no` fails accessibility audits); the board uses `touch-action:none` and the body `touch-action:manipulation` instead.
- Piece animations must not scale (pieces are positioned with `transform: translate`, scaling shifts them).
